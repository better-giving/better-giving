## The seats

Load **`kru:lead`** before building, reviewing, or dispatching a seat — it carries how the team works.

| **skills**                           | `drizzle` · `zod` · `conform` · `xstate` · `react-email` · `vitest` · `api-design` · `tui-design` | `drizzle-orm` 0.45.2; `zod` 4.4.3 and `@conform-to/react` 1.21.1 pinned once in the catalog and declared by `packages/app` and `packages/console-ui` alike, so a console form's rules ride the same two skills; `react-email` 6.9.3 in `packages/emails-preview` and `@react-email/render` 2.1.0 in `packages/emails`; `vitest` 4.1.10 in every package that tests — from the catalog, and pinned to the same version in `packages/zapier` — so the skill's v4 column is the one that applies, and `@vitest/browser-playwright` 4.1.10 in `packages/form` alone; `api-design` for the surfaces other people's code calls — `/api/v1`, the Zapier key the app mints and the hooks it posts to; `xstate` 5.32.5 in the catalog, declared by `packages/form` for the machine and by `packages/app` for the actor the donation page builds on it, and no `@xstate/react` anywhere, so the react half of that skill is not this repo's; `charmbracelet/bubbletea` 1.3.10 in `packages/console/go.mod` with `bubbles`, `huh` and `lipgloss`, and it is v1, so that skill's v2 import-path split is not this repo's either |

`/reset` and `/release` are this repo's own and the user's to type (`.claude/skills/`). `/reset` tears the dev deployment down and packs a fresh bundle, so `pnpm console` sets up from nothing; `/release` cuts the `v*` tag that `.github/workflows/release.yml` builds the console binary and the worker bundle from.

A slice reaching a stack no seat above covers is a question for the user, naming the seat it would need — never a nearby seat pressed into the gap.
