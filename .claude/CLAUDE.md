# better-giving

Self-hosted donation forms for a single organisation. One deployment serves one org; a fork is how a second org gets one.

## Where a rule lives

Three homes, and putting one in the wrong place is how it gets stated twice and drifts.

- **A stack's generic mechanism belongs to a tooling skill, not to this repo.** It arrives with the seat, and nothing here re-derives it.
- **A rule about one file lives in that file's header comment.** That is where someone changing the thing is already looking, and it is why the headers in this repo are long on purpose. `## The map` says which file owns what.
- **This file states the rule and names the pointer; the argument for it lives at the pointer.** What earns a line is what you could break without ever opening the file that owns it — a ban, a one-way door, a seam, a permanent contract. A reason restated here is one that drifts from the header it was copied out of.

## Two operator surfaces

**The dashboard** is `/admin` on a deployment. **The console** is a binary the operator runs on their own machine: `packages/console`, the Go module that holds the Cloudflare sign-in, answers `/api`, and serves `packages/console-ui`'s build out of itself — the React app whose every read and press is a call back to that binary. Neither is ever deployed anywhere, and `packages/console-ui/src/never-deployed.spec.ts` holds the four absences that make that structural. A sentence about both says **operator screens**, and neither word ever means a terminal window: where one is meant, say terminal.

**The deploy is one terminal command and no screen draws it.** `better-giving start` stands a deployment up where there is none and offers to carry this release's code onto one that is behind, and `better-giving update` installs the console binary and reaches no deployment at all; both run in the terminal the operator typed them in, neither reaches the binary's `/api` at all, and the console's screens hold every value and one re-connect gate and run no long job but the Stripe keys. `packages/console/cmd/better-giving/start.go` and `update.go` argue the split, and `packages/console/internal/terminal` is what draws a run.

**The split is singletons against collections.** The console holds the one true thing about this deployment and this organisation — the Cloudflare account, the database, the thirteen configuration values, the Stripe keys, the site list, the legal identity. The dashboard holds the records: donation forms, donations, donors, recurring gifts. A screen drawn on the wrong side of that line is what this rule exists to name.

**The dashboard is not served at all until set-up is finished, which is what lets every screen under it assume it is.** The five jobs are `packages/operator/src/setup-folds.ts`'s `SETUP_JOBS`, read on the deployment by `packages/app/src/lib/server/config/readiness.ts` and gated once, in `packages/app/src/routes/_app.tsx`'s loader, which draws `$lib/admin/setup-gate.tsx` in place of every child. **`FOLD_LABELS` names six folds and `SETUP_JOBS` is five of them** — the sixth is no job and the deployment waits on it for nothing, so reaching for the wrong list is that gate held shut on a deployment already taking gifts. **The reading repairs nothing, probes nothing, and a read that did not land gates nothing.** `setup-folds.ts` argues which list is which; `readiness.ts` and the loader argue the other three.

**Seven packages under `packages/*`** — `app`, `console-ui`, `emails`, `emails-preview`, `form`, `gallery`, `operator` — **and the graph is `app → operator ← console-ui`, with `gallery → operator`, `emails → operator`, `app → form` and `app → emails ← emails-preview` beside them.** No consuming package reaches another and the leaves reach none, so a module wanting an app component stays where it is and only its callers move. **A module arrives in `packages/operator` by being promoted, never by being copied** — the copy that would have been the cheaper answer is how two surfaces come to disagree. `packages/emails` is the mail templates — dressed from `packages/operator`'s tokens through `packages/operator/src/styles/tokens.ts`, the same values as text, converted to hex and pixels by `packages/emails/src/tokens.ts`; it reaches nothing else in this repo and is rendered to strings by the app at send time. `packages/emails-preview` is dev-only, exactly like `packages/gallery`.

Two directories sit beside the seven and are not packages, both for want of a `package.json`, so both are invisible to the workspace glob and to every `pnpm -r` command. `packages/console/` is the console's Go module. `packages/design/` holds artboards a screen was drawn from, on the machine that drew it: **it is ignored by git and no artboard is ever committed**, and **no design rule is written there and none may be**.

`packages/form/` and `packages/app/src/lib/forms/` are the pair to keep straight, and the axis is **permanence, not client-versus-server reach**. Everything in the package is a permanent contract; nothing in `forms/` is, and a name may change there and may not in the package. Code moves between them only when someone decides it is permanent, never by proximity. Anything under `$lib/server/**` may import from the package; the package imports from nothing in this app.

**A value the app needs from an eighth module of `packages/form` is a decision to widen its `exports` map out loud, never a line added to it in passing** — the embed ships into a stranger's page.

## Design system

Two of them, one per audience, and each is a token file that is the closed source of every value on its side. What each holds and why is in the header comment of the file itself:

- **The donation form** — `packages/form/src/styles/tokens.css`, with `packages/form/custom-elements.json` as the canonical list of what an integrator may set.
- **The operator surfaces** — one system dressing both of them, and the component gallery beside them: `packages/operator/src/styles/tokens.css`, with `base.css` holding the reset and the document defaults, `adm.css` drawing every `.adm-*` class, and each surface's own `app.css` importing the chain in that order. The split is where a rule goes as well as where it is written: an element an operator screen draws as a thing is a class in `adm.css`, and everything left is `base.css`. A comment pointing at the wrong one of those two sends a reader to a sheet that does not contain the rule. Each surface gates its own screens and hands its file list to the one assertion in `packages/operator/src/styles/raw-values.ts`; `tokens.css` names the five gates. What a gate globs is per-surface; what counts as a violation is not.

**`packages/gallery` is a dev-only page — `pnpm run gallery` — and not an operator surface.** It renders every component `packages/operator` publishes in the states nobody opens, is never built and never deployed, and answers no question about a deployment. `packages/gallery/src/previews/` is globbed rather than listed, so a component's preview is registered by the file existing.

**A value a screen needs and the token file cannot express is a gap to report, never one to invent.** A deliberate exception is a `raw-colour-ok:`, `raw-length-ok:` or `type-ok:` note on the line or the comment directly above it, never a change to the gate.

## Bans

**The ledger**, argued in `posting.ts`'s header — the only module that may insert, gated by `sole-writer.spec.ts`. Every total is a `SUM` at read time: no running balance is stored and none is gated on. Multi-row writes go in one atomic `batch()` — `Db` `Omit`s `transaction`, so reaching for one is a compile error. No invariant is enforced by an atomic read-then-write, and a lost race is settled by a correcting entry rather than a rollback. **A SQLite-backed Durable Object is not the escape hatch.** Reopen any of it out loud or not at all.

**Storage.** D1 is the database and there is no second one. `packages/app/src/lib/server/db/client.ts` is the only module that names it; everything else takes `Db`. **D1 read replication stays `disabled`**, argued in `posting.ts`'s header. **The edge cache in front of the served form config is not an exception to that** — it holds a capability and not money. Cite it as precedent for caching a capability, never for caching a number.

**Repeating gifts**, each argued in `collect.ts`. A commitment's row is written by the **first charge that settles**, from what actually moved, and `collect.ts` is the only module that may `INSERT` into `recurring_plan`, gated by `sole-inserter.spec.ts` — an authorization is not a collection. **The gift itself is recorded at authorization**, on both cadences alike: a `donation` with no successful `payment` reads as `pending` and claims no income. **The first settled charge claims that row rather than inserting a second** — the opening month counted twice is what the claim exists to prevent. **No name a donor typed reaches the processor**: a commitment carries pointers and figures only, and the dedication stays on the gift's own row. **The donation path never gates on the recurring capability**: a cadence the deployment cannot charge is not offered to the donor in the first place, so a submission that arrives anyway is charged rather than refused.

**Schema shape.** Single-tenant: no `org_id`, no row-level security, no tenancy seam. **No mechanism may let an org add a column** — extension is a JSON column plus a registry, and crossing D1's 100-column limit must require a migration under review. Model the domain past what the UI renders.

**Migrations are never an app-boot side effect.** Two paths touch a production schema and no other may: the `deploy` script from a checkout, and `better-giving start` (`packages/console/internal/migrate`). Each remote migration is a one-way door. Everything able to fail runs in front of that door — the build, then `packages/app/scripts/preflight-deploy.js` — and the script itself in `package.json` is the order of record. **Never move a step behind the door, and never gate on a command that does not pass.** The suite and the type check gate `git commit` through `lefthook.yml` instead, because a deployer changes no code. **No remote CI gates a commit** — `.github/workflows/release.yml` runs on a tag and gates nothing.

**Runtime.** Nothing built from a binding is a module-scope singleton — the D1 handle, the auth instance and the Stripe client are constructed per request from the env that request arrived on, seeded onto the router context once in `src/request-context.ts` and taken from there (`src/context.ts`). **The request body is read exactly once, by the endpoint that owns it**; a hook that touches the Stripe webhook's body breaks signature verification at runtime. Reads are `loader`s; writes are `action`s or endpoints — no client-side mutation paths in `/admin`.

**Dependencies are exact — no `^`, no `~`, in either block.** The lockfile pins what installs; exact ranges pin what a _resolution_ may become. **The `wrangler` pin must equal the version `@cloudflare/vitest-pool-workers` depends on**, or the tests run on a different `workerd` build than `deploy` uses — bump both together or neither. Wrangler is invoked as `pnpm wrangler`, never global, never bare `npx`.

**Boundaries.** Payments go through the `PaymentProvider` port, never a processor SDK directly — gated by `packages/app/src/lib/server/payments/sole-importer.spec.ts`. Email goes through the `EmailProvider` port and **SMTP is the interface** — never a vendor SDK, and **nothing selects a transport**. **Secrets live only under `packages/app/src/lib/server/**`** and are deploy-time, never rows in a settings table; the one carve-out is a key the app mints for itself. **Every one of the thirteen configuration values is a plain Worker var, never a Worker secret**, so the console can show what is stored — `packages/operator/src/deploy-split.ts`'s header argues it, and `packages/app/src/lib/server/config/deploy-split.spec.ts` sweeps the tree for a command that would store one the other way. The console's own session token is the one Worker secret, and it is on no enumeration. **`/api/v1` is public, unauthenticated and payment-initiating** — never add an endpoint there without CORS from the form's `allowed_origins`, rate limiting, Turnstile, and server-side amount bounds re-checked against the form record. **`Origin` is an attribution signal, never an authorization control.** 4xx bodies are read by agents, not humans: name the offending value and where to fix it.

**Forms.** Every box a form states must arrive, without exception. A form seeded from a record reports no error until it is submitted. Schemas stay flat, and a body naming a value inside another is refused. **The staff password is never echoed back.**

**Two design systems, and they never meet.** `/admin` **derives no colour from anything an integrator can set** — not a `--donate-*` seed, not a `::part()` name. It does import the form's _vocabulary_ and must keep being able to. **No `/admin` screen gets a `*.browser.spec.ts`** — the form has them because its CSS is a contract; `/admin` is free to change and a browser test would freeze that.

## Permanent contracts — add, never rename

**Nothing here is deployed for real yet, and nobody has pasted the snippet.** One test deployment, no organisation operating on it, no donor page in the wild carrying `v1`. So a contract below is permanent *by decision* rather than by exposure: weigh a fix on its own merits and correct the contract outright rather than versioning around it. Every argument here that turns on sites we cannot reach is the reason the contract exists, not a live cost now. **Delete this paragraph the day a real organisation deploys**, because every line under it becomes true again in the same moment.

- **`v1`.** The snippet is pasted into sites we cannot reach; breaking changes ship as `v2` alongside.
- **The element's public style surface** — `--donate-*` seeds and `::part()` names. Everything derived from a seed is `--_`-prefixed and private. `packages/form/custom-elements.json` is the canonical list and ships in the same commit as any change.
- **The element's public attributes stay primitive.** One object-valued attribute makes React support version-dependent.
- **The resume stamp `bg_donate_form`** — `RESUME_FORM_PARAM` in `packages/form/src/embed/resume.ts`, which argues why. It follows no other name in the repo, the element's tag included.
- **Operator commands run at the repo root.** The root `package.json` forwards every operator script into `packages/app`, and `DEPLOY.md` is written against those root commands — a forwarder that stops forwarding breaks the documented path for every fork at once. From inside a package directory the spelling is `pnpm -w run <script>`. Packages land in `packages/*`.
- **The embed reaches the worker only through `build`'s three steps, in order** — `packages/form` builds into its own `dist/`, `packages/app/scripts/stage-embed.js` copies that into `packages/app/static/`, and `vite build` copies `packages/app/static/` whole into the client build. Drop or reorder the middle step and the build stays green while `/embed.js` 404s. `packages/app/scripts/preflight-deploy.js` is the only thing that catches it, and it catches it by counting files rather than by reading this chain — so a step moved behind it is a step nothing checks.
- **`main` in `packages/app/wrangler.jsonc` is the worker entry's source, and there is no `assets` block.** `@cloudflare/vite-plugin` reads that file and writes the config `wrangler deploy` uploads, so a deploy uploads what the *build* named. **The environment is chosen at build time, by `CLOUDFLARE_ENV`, and `--env` on the deploy cannot change it** — a build made without the variable is the top-level configuration, and wrangler uploads it under `--env test` without complaint. `pnpm run deploy:test` sets both, and `preflight-deploy.js` refuses the pair when they disagree.

## Product surface

- **The donor-facing page is `/{form_id}` on the deployment**, `packages/app/src/routes/$formId.tsx`: one top-level segment, drawn server-side from the same published config the served config endpoint hands the embed and refusing on the same ladder. **it exists so that set-up can finish without a website**: the spam protection is registered against the sites a form is served on, and an organisation that has none had nothing to name. **it is not a site an operator ticks** — it is on no `site` row and on no form's `allowed_origins`, and the deployment accepts its own origin off the request instead (`packages/app/src/lib/server/api/cors.ts`, and `acceptableHostnames` in `packages/app/src/lib/server/donations/quote.ts`), so nothing an operator can untick takes their own donation page down. **and it is not a rehearsal surface**: a gift made on it is a real gift on whatever keys the deployment holds, because nothing in this project reads test-versus-live — rehearsing is a second deployment (`DEPLOY.md`). The route's own header argues the whole of it.
- **This deployment serves no auth HTTP API.** better-auth's router is never mounted — no route file answers `/api/auth/*` — so those paths are a 404 rather than a surface switched off. sign-in, session and sign-out are direct `auth.api.*` calls from a route's own action or middleware. it is stated here because a surface that disappears by nobody writing a route file is a surface nobody reviews: `packages/app/src/routes.spec.ts` holds the absence and `packages/app/src/lib/server/auth/index.ts` argues what it costs, so a fork reading these rules does not go looking for an API this app does not answer. **the one bucket that bounds password guessing is charged at the login's own action** — one payer, on `signInRateLimitKey` in `packages/app/src/lib/server/api/rate-limit.ts`, and a second way in spends that same key rather than minting one.
- **The repo contains no org-editable files** — that is what keeps a deployment a clean fork and an upgrade a pull rather than a merge.
- **No deployment artifact is committed** — not a `database_id`, `account_id`, `zone_id` or deployed hostname. A fork inherits the config, so any of them is a pointer at something the fork cannot reach. Resources resolve by name. The trap: **`wrangler d1 create` offers to write the id back into `packages/app/wrangler.jsonc` and defaults to yes** — pass `--no-update-config`. The Worker `name` is not an artifact by this rule, and seeded UUIDs in `packages/app/migrations/` are not either.
- **The form's flow logic imports no framework.** One machine and one `v1` client under `packages/form/src/`; every adapter consumes it, never copies it.
- **UI strings say what a fundraiser says.** The schema models more than donations and its table names show it; those names never reach a screen — no _constituent_, _activity_, _soft credit_ in user-facing copy.

## Comments

- **A comment states the rule, never the deliberation that produced it.** No rejected alternatives, no libraries evaluated and not chosen, no "X rather than Y" where Y was never here. Naming a package that is not in `package.json` sends the next reader to look up something irrelevant.
- **A comment must be complete to someone holding only this repository.** Never cite a document that is not in the tree. Anchor a claim to a `file.ts:line`, a test name, `CLAUDE.md`, `README.md`, `DEPLOY.md`, `CONTRIBUTING.md`, or a public URL. `ls` at the root is the whole test.
- **Comments are lowercase prose, and nothing is emphasised by shouting it.** A shouted noun phrase reads as the title of a document, which mints a dead pointer without anyone naming a file. Capitals are for what is genuinely uppercase: acronyms, SQL keywords, `SQLITE_*` codes, env-var and constant names, and files spelled that way.
